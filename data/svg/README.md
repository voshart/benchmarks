# SVG tracer evidence

`results.json` supplies `/svg/` and `/svg/data.json`. `evidence/` contains aggregate measurements, provenance and a renderer diagnostic. These records combine local runs from 4 November 2026 and published source checks through 5 November 2026, not a live execution harness or independent certification.

## Protocols

- `fonts-full-20261104`: all 4,821 SVG-Fonts test inputs, 256 px white-background resvg input, original framing. Matched 1024 px output/reference geometry renders, errors converted to native pixels. DINOv2-base FP32 scores matched 256 px resvg images; all last-layer tokens are averaged, cosine mapped to `(cosine + 1) / 2`.
- `icons-full-20261105`: all 2,682 released `starvector/svg-icons` test inputs (revision `0dfc1bee713256e64d5c16d7427c4c29de823d70`), same renderer, scorer and metrics as the full fonts run. Stroke-only line art rendered to 256 px inputs; Monotrace and Potrace 1.16 only. The kernel source revision matches the font run, but the binaries were rebuilt and output equivalence was not tested. Three explicit Monotrace refusals stay in every denominator. The split is observed material, not a tuning holdout. Evidence: `evidence/full-icons-summary.json`, `evidence/full-icons-provenance.json`; the per-case archives stay in the private Monotrace repository.
- VTracer 0.6.15 (binary mode, library defaults, one untuned configuration, same 256 px input as Monotrace) was added to both full runs on 5 November 2026 from the Monotrace maintainer's packaged summaries (monotrace commit `ec64742`). Potrace and Monotrace rows are unchanged frozen results. Its full-font row takes priority over its pilot row, which remains an alternate observation. Evidence: `evidence/full-fonts-vtracer-*.json`, `evidence/full-icons-vtracer-*.json`.
- AutoTrace (git tag 0.31.10, reports 0.40.0; `autotrace -color-count 2 -output-format svg`, every other option at the tool's default, one configuration declared before scoring) was added to the full Fonts and Icons runs and the PolyFit run on 5 November 2026 (monotrace commit `dde25fa`). Input is the same 256 px file flattened onto white as RGB. Plain defaults traced every antialiasing level as its own region in an unscored three-image check, hence the single-ink setting. Segment counts include its white background path; three Fonts outputs render with no ink and carry the 256 px penalty. It scores below Monotrace, Potrace and VTracer on DINO in both full splits. Evidence: `evidence/*autotrace*.json`.
- `fonts-pilot-20261104`: 256 cases selected by the lowest SHA256 values of `monotrace-external-first-pass-v1:` plus source filename. This subset is contained within the full run. VTracer was run only on this font subset.
- `polyfit-binary-20261104`: all 116 original monochrome raster inputs, native sizes and matched resvg output rendering. No original vector masters; the PolyFit algorithm itself was not executed.
- `svg-fonts-published-2025`: the pinned StarVector authors' SVG-Bench table. Author-reported StarVector results and competitor-reported baselines. Exact evaluated count and original baseline invocations remain unverified. The raw protocol is retained separately inside the unified matrix; it does not establish a matched local-versus-published win.
- `mmsvg-icon-omnisvg2025` and `mmsvg-illustration-omnisvg2025`: OmniSVG (NeurIPS 2025), Table 2 image-to-SVG columns. Each paper-defined subset has 150 synthetic GPT-4o raster inputs. DINOv2 cosine, SSIM, LPIPS, MSE and rounded average Qwen2.5-VL token lengths are retained. The Hub card corroborates the table; the exact paper-era evaluation files and renderer settings were not reproduced. The paper's 4B/8B configurations do not inherit later OmniSVG releases.
- `layertracer-vectorization-2025`: LayerTracer (ICCV 2025), Table 2 and Section 4.1's 50-image selection. Retains MSE, average path counts, layer-wise metadata and reported time in Details. Exact case list, source proportions, scoring normalization and inference timing environment are unverified. The text generation comparison and separate nine-frame ablation are excluded.

`evidence/published-tables-2025.json` records the transcribed source cells, table locations, attribution and primary URLs for these imports. Publisher self-reports and competitor reports are explicit per row. No model was executed for this import; source verification is not independent reproduction. Mean paths, median geometric segments and tokenizer lengths have separate metric keys. Published DINOv2 cosine is also separate from the local font scorer's rescaled DINO metric. Raw values from different protocols are not averaged. The unified index normalizes quality only within each exact protocol before summarizing dataset families, as described below. Source-specific published time costs are preserved as attributed context, not a cross-study speed ranking.

## Ranking and presentation

The page has **one comparison matrix**, with all local and published configurations including Monotrace. There is no source selector, second leaderboard or separate incomplete-results table. The default shows all colours; the colour selector filters measurements by dataset scope. Search and column sorting operate on that matrix. Ordinal rank is visible and recalculates for the colour view; an unchanged index means the contributing measurements stayed the same. Monotrace currently has only monochrome measurements (fonts, SVG-Icons and PolyFit), so its index is unchanged between All and Single colour even though its ordinal position changes. The compact mobile table uses explicit column widths, a fixed rank/name pair, optional complexity columns and horizontal scrolling for additional datasets. Complexity columns are optional. All default rows and source details are rendered by Eleventy without JavaScript; the browser uses the same pure matrix calculation.

The relative index reuses the shared speech benchmark's finite-cohort percentile function (`ranking.js`, `pctRanks(..., true)`). On each exact protocol with at least two scored configurations, order its declared quality metric and assign `100 * (n - midrank + 0.5) / n`; ties share the midpoint percentile. For each configuration, average its available percentiles **once per dataset family**, without filling missing scores. One family is enough for a qualified index; fewer than four is explicitly limited coverage in the index details. The number of contributing families is visible under Tests. This is a descriptive relative summary of different reference cohorts, not accuracy, population confidence, or a matched win over every row. No direct local win over StarVector or AutoTrace is established by this index.

Protocol preference is explicit in `runs[].priority`, ascending, with ID as deterministic tie-breaker. Full local fonts take priority over the contained pilot for configurations measured in both. VTracer retains its pilot measurement; every alternate stays available in the font cell's details. A repeated run cannot create a second font-family vote. Priority never selects the highest score. Missing/solo results do not supply a percentile or a loss. The legacy five-dataset `overview` definition remains a reproducible same-source descriptive mean in the downloadable definitions; it is neither a separate visible table nor an extra index vote.

Exact configurations remain separate rows, identified by the small configuration label under the method name. In particular, local Potrace 1.16 is not merged with an unversioned paper baseline, binary VTracer is not merged with a paper's colour pipeline, and StarVector fine-tunes are not assumed to be one universal checkpoint. Publisher and competitor attribution remains per observation. This avoids inventing cross-study binary/checkpoint equivalence merely to connect a ranking graph.

Colour scope is declared in `matrix.columns`: Single colour contains font glyphs, SVG-Icons and original binary PolyFit rasters. The complete pinned released SVG-Icons test parquet contains 2,682 SVGs: all paths have opaque black strokes, no fill, and no gradients or embedded images. The earlier multicolour classification was incorrect. Multicolour contains the remaining colour/mixed datasets. It is a broad dataset category, not a claim that every image is multicolour or that a tracer supports every colour feature. The published aggregates do not isolate flat-only and gradient-only cohorts. The Gradients option therefore shows an explicit no-measurements state; no gradient score is inferred from mixed-colour aggregates. A new gradient-only result should get its own exact protocol and declared family, not a copy of an existing score. Colour selection precedes index calculation; search, complexity visibility and display sorting follow it.

Complexity, runtime and failure diagnostics never supply quality votes. The optional segments, paths and tokens columns retain distinct units and show one attributed measurement, selected by the same declared protocol order. Each cell identifies its originating dataset and full metric set in keyboard-accessible details. No cross-dataset complexity mean or shared timing rank is invented. Input dataset token statistics are not output complexity. Missing values sort last in either direction; measured zero is preserved. Full source precision determines percentiles and index; rounding is display-only.

`evidence/starvector-models-2025.csv` preserves all cells in the pinned Models table, including unavailable diagram scores for Im2Vec and GPT-4-V. `starvector-provenance.json` records the revision and import policies. The original font observation and all other raw measurements are unchanged. Source verification is not independent execution.

It preserves both sources and the pilot/full distinction. Renderer, scoring size, input treatment and baseline versions differ or remain unverified; a 64-image diagnostic did not resolve the gap. These are reproduction differences, not measurements under the same verified protocol. All observations are visible in one matrix. Local scores do not fill missing published observations. Monotrace’s index uses only its matched local tests and remains a sparse, qualified summary.

## Failure and metric policy

Font-run geometry means include every image. Empty output against visible reference receives a 256 px boundary penalty; blank against blank is zero. All four completely white references remain in the full test. Monotrace has two explicit trace errors plus two completed empty outputs against visible reference; Potrace has one completed empty output against visible reference. The separately labeled conditional mean uses the same 4,813 paired successful nonempty cases and excludes those failures and empty images. It must not replace the all-case mean.

Monotrace leads on full-run DINO and median boundary error. Potrace leads on the all-case mean after empty-output penalties, and on the PolyFit raster IoU/boundary comparison. Sampled topology mismatches are not exact vector-topology certification. Segment counts describe complexity and do not prove reconstruction quality. DINO is not a percentage accuracy or a guarantee of good curves.

## Adding evidence

Keep exact configuration identities in `models`, metric definitions in `metrics`, and operator/attribution/primary URLs in `sources`. Each `runs` entry names a dataset source, result source, sample count (or `null`), primary quality metric, visible columns and one row per model/configuration. `matrix` defines the unified display, colour scopes and index coverage rules; `runs[].family` and `priority` determine family selection. `models[].configuration_label` identifies source/version variants. `overview` retains the legacy fixed same-source descriptive panel definition without stored mean observations or an index vote. Metric roles distinguish quality, complexity, diagnostics and time. `differences` references both observations rather than copying display numbers. Row `values` are finite nonnegative numbers or `null`; unknown metrics are rejected. Conditional cohort size and exclusions must be explicit.

Reuse a group only when dataset, preprocessing, scorer, resolution and execution conditions match. Different versions or paper protocols get new exact configuration/protocol records within the matrix. Do not fill unavailable scores with zero, import source code from private repositories, or declare a direct win across different groups. Open a primary source before changing any observation. Run `npm run format` and `npm run build`, then verify `/svg/`, its filters/details and data downloads on the deployed commit.

## PolyFit caveats — 5 November 2026

`evidence/polyfit-paired-analysis.json` (with provenance) is the maintainer's paired analysis of the 116 PolyFit inputs. They are 58 artworks at two size labels, which are not pixel sizes, so the effective sample is at most 58. Monotrace minus Potrace IoU is −0.0030 (bootstrap 95% interval [−0.0059, −0.0003] per case; [−0.0060, −0.0002] per artwork), concentrated at the `-32` label (−0.0057) and indistinguishable from zero at `-64` (−0.0004). There are no ground-truth vectors: IoU and boundary error measure fidelity to the thresholded raster, so a lower score is not evidence of a worse contour. A three-row percentile index magnifies this small gap. The unused `data/multicolor` folder was not run; Monotrace is a single-ink kernel and it is not suitable for the single-colour cohort.

## Input-size sensitivity — 5 November 2026

`evidence/inputsize-*` records a diagnostic by the Monotrace maintainer (monotrace commit `39487f3`): does the size of the image given to each tracer explain the gap between our Potrace/VTracer scores and the published StarVector-table scores? **Not confirmed.** Tracer input size moves DINO by about 0.02 per step between 96 and 128 px, as large as the gap to the published baselines, but no single size reproduces the published values on both corpora and the pre-declared test failed (the pre-declaration is a local file with a recorded hash, not independently timestamped). Fonts implies roughly 105–111 px for both baselines, a post hoc observation. Icons implies about 150–170 px for Potrace and about 97 px for VTracer, and the published Icons ordering (Potrace well ahead of VTracer) cannot come from a shared input size. The cause of the published scores is unknown.

This does not show that any published run was weak or unfavorable, is not a head-to-head with StarVector, and adds no matrix rows or ranks. Monotrace at 96 and 128 px leads on DINO and median boundary error in that study but has more trace errors on Icons (6 and 4 of 2,682, against 3 at 256 px); these protocols are not part of the ranking. Both full splits remain observed material, not holdouts. The pilot sweeps (256 cases) and per-case results stay in the Monotrace repository.
